## 目的

让 UI 方案从一开始就像微信小程序，并能转换为原生 WXML/WXSS/JS/JSON。HTML 只承担可点击预览和并排比较，不得用网页设计习惯决定页面结构，也不得把通用 Web UI Skill 作为默认设计来源。

## 来源优先级

按以下顺序获取设计依据：

1. 微信官方[小程序设计指南](https://developers.weixin.qq.com/miniprogram/design/)和平台组件规则。
2. 项目已有品牌资产、截图、设计 token 和组件。
3. 一个成熟的小程序组件体系：WeUI、TDesign MiniProgram、Vant Weapp 或原生组件。
4. 已安装的小程序或移动 App 设计 Skill。只借用需求提问、手机框比较和设计检查方法；不得直接继承其 Web 技术栈、现代 CSS 或平台假设。
5. 社区模板和案例。使用前检查当前版本、许可证、维护状态和页面是否适合本项目，不按 Star 数自动采用。

没有合适第三方 Skill 时，直接使用本文件完成设计，不回退到通用网页设计流程。

## 设计输入

首版范围确认后，只补问会改变 UI 的缺失信息。优先使用结构化提问工具，一轮最多 1-3 个问题：

- 用户更希望“像微信、容易上手”，还是“有自己的品牌感”；不确定时保留两种方向供比较。
- 是否已有 Logo、品牌色、参考截图或必须复用的界面。
- 主要在现场快速操作、日常反复查看，还是需要大量填写；这决定信息密度和主操作位置。

不要让用户用抽象设计术语描述风格。用户没有视觉偏好时，直接生成三套可见方案让他比较。

## 已有项目样式继承

继续已有项目时，先建立样式基线再修改 UI；新项目仍按下一节生成三套方案。基线至少来自：

1. `app.json` 的 `window`、`tabBar`、主题和页面配置。
2. `app.wxss`、公共 WXSS、主题文件和设计 token。
3. 目标页面 WXML/WXSS/JSON、公共组件和当前主组件库。
4. 项目内图标、图片比例、空/错/加载状态及现有真机截图。

在 `docs/miniapp/design-system.md` 记录以下可复用事实：

| 类别 | 记录内容 |
| --- | --- |
| 视觉 token | 主色、辅助色、字号层级、间距、圆角、边框和反馈状态 |
| 页面结构 | 导航、内容层级、列表/表单模式、底部操作和安全区 |
| 资源 | 主组件库、公共组件、图标来源、图片比例和裁切方式 |
| 数据映射 | API/存储字段如何显示、空值与异常值如何降级 |
| 差异 | 无法继承的部分、原因、影响页面和回归范围 |

新增页面默认继承现有项目的 token、组件和交互习惯。不要从外部案例照搬固定 `vw`、字号、4px 圆角或统一卡片结构；现有项目基线优先，同时仍满足微信胶囊、安全区、触控区域和 WXML/WXSS 可落地要求。用户明确要求整体改版时，才重新走三套方案比较和完整视觉回归。

## 三套方案合同

把三套方案保存到 `docs/miniapp/ui-options/index.html`，用同一关键页面、同一业务数据和同一功能范围公平比较：

1. **A 微信原生稳妥方向**：以 WeUI 和原生组件为参照，系统字体、克制层级、最低实现风险。
2. **B 品牌定制方向**：以 TDesign MiniProgram 为主要组件基座，调整颜色、圆角、密度和内容层级，不改变微信导航习惯。
3. **C 差异化可落地方向**：视觉辨识度明显高于 A/B，但核心效果必须能由 WXSS、项目内本地图片或轻量动画实现。

如果项目已经确定主组件库，三套方案都基于该组件库，只改变视觉和布局表达。不要为了凑满三套而混用组件库。

比较页面可以使用普通 HTML 排列手机框；手机屏幕内部必须遵守以下要求：

- 固定使用 375px 或 390px 宽的竖屏画布，并在整个项目保持一致。
- 显示状态栏、微信右上角胶囊、顶部避让区和底部安全区。
- 使用真实中文文案和接近真实的模拟数据，不使用 Lorem Ipsum、Hero、营销口号或设计流程说明。
- 三套方案必须展示真实产品首页或最高频任务页，不能只展示色板和组件样例。
- 显示底部导航时采用 2-5 项，优先不超过 4 项；每项有正常态和选中态。
- 每个可点击区域至少约 44px；交付到小程序时对应约 88rpx 的舒适点击区域。
- 方案名称、实现难度和差异说明放在手机框外，不污染真实界面。

用户看过比较页面后，优先用结构化提问工具让他选择 A、B、C、组合明确元素或继续修改。用户未明确选定前，不生成完整高保真原型。

## 小程序硬约束

| 设计问题 | 必须采用的处理 |
| --- | --- |
| 微信胶囊 | 预览中固定显示并留出空间；开发时用 `wx.getMenuButtonBoundingClientRect()` 动态计算，不硬编码真机位置 |
| 顶部导航 | 标题、返回和页面操作避开胶囊；自定义导航必须说明返回路径和系统状态栏适配 |
| 触控区域 | 关键按钮、图标按钮和列表操作至少约 88rpx；视觉图标可以更小，点击区域不能缩小 |
| 底部安全区 | 固定按钮、自定义底栏使用 `env(safe-area-inset-bottom)`，并在 iPhone 和安卓真机检查 |
| 原生 `tabBar` | 图标使用项目内本地 PNG，同时准备 `iconPath` 和 `selectedIconPath`；不使用网络图片、SVG、iconfont 或 emoji |
| 自定义 `tabBar` | 仅在原生样式确实无法满足已确认方案时使用；必须处理选中态、页面同步、安全区和所有入口回归测试 |
| 字体 | 默认使用微信运行环境的系统字体；不依赖 Google Fonts、远程字体或未授权字体 |
| 图片和图标 | 优先使用主组件库图标或有许可证的项目内资源；关键文字不能做成图片 |
| 状态 | 数据页面至少设计正常、加载、空、错误；涉及权限时再增加拒绝授权和重新操作路径 |
| 适配 | 检查窄屏、长文字、字体放大和键盘弹出，不照搬桌面多栏或固定宽度网页布局 |

## WXML/WXSS 可落地门禁

用户选定方向后，生成完整原型前先检查每个核心视觉和交互。把结果写入 `docs/miniapp/design-system.md`：

| 原型元素 | 小程序实现 | 组件来源 | 风险或降级 |
| --- | --- | --- | --- |
| 主按钮 | `<button>` 或对应组件 | 当前主组件库 | 加载、禁用、按下态 |
| 页面卡片 | `<view>` + WXSS | 原生或当前主组件库 | 阴影和圆角在安卓真机检查 |
| 底部导航 | 原生或自定义 `tabBar` | `app.json` 或组件 | 本地 PNG、选中态、安全区 |
| 顶部导航 | 原生导航或自定义导航 | 微信平台能力 | 胶囊动态避让 |

每个承载品牌识别或主要操作的效果都必须有明确的小程序实现。找不到可靠实现时，按顺序处理：

1. 改成 WXSS 可实现的等价效果。
2. 适合静态装饰时，预渲染为已授权的本地 PNG/WebP，并记录体积与适配方式。
3. 仍不可行时，从候选和原型中移除，不能只在交接文档写“开发时再想办法”。

禁止把以下内容作为核心视觉或主要交互：

- Landing Page、Hero、桌面导航、转化漏斗、社交证明等网页结构。
- Three.js、WebGL、GSAP、视差、鼠标 hover、键盘专属交互。
- `backdrop-filter`、复杂 `clip-path`、`:has()`、容器查询或滚动驱动动画。
- 远程 CDN 图标、远程字体、外链脚本、需要浏览器扩展或 Web 运行时的能力。
- 只能在 HTML 中成立、没有 WXML/WXSS 映射的装饰和组件。

非核心装饰若使用现代 CSS 方便预览，也必须提供已验证的降级效果；关闭该效果后，信息层级和品牌识别仍应成立。

## 组件选择

- **WeUI / 原生组件**：适合快速上线、微信原生感、轻量表单和设置流程。
- **TDesign MiniProgram**：默认优先评估，适合表单、列表、数据、工具和业务流程，并允许品牌 token 定制。
- **Vant Weapp**：适合已有 Vant 项目或组件模式高度匹配的移动业务；不要只因为组件数量多就采用。
- **自研组件**：只在现有组件库无法满足关键品牌或交互时增加，不能重造基础按钮、表单和反馈组件。

一个项目只选一个主组件库。设计阶段只记录选型和来源；除非用户已经授权进入开发，不安装依赖、不复制模板源码。

## 原型与交付

选定方向后，完整原型至少覆盖 3-5 个相连页面或状态，证明用户能完成首版核心任务。原型使用手机画布、真实文案和可点击跳转，并覆盖导航、主要表单、加载、空、错误和拒绝授权状态。

`docs/miniapp/design-system.md` 至少记录：

- 375px 或 390px 画布基准和胶囊避让方式。
- 方案来源、参考链接、版本快照、许可证和采用/舍弃原因。
- 颜色、字号、间距、圆角、按下态和状态反馈 token。
- 主组件库及每个关键组件的 WXML/WXSS 映射。
- 原生或自定义 `tabBar`、本地图标清单和安全区方案。
- HTML 专用效果、对应降级方式和仍未完成的真机验证。

始终告诉用户：HTML 原型用于确认视觉和流程，不是最终小程序；最终效果以微信开发者工具和安卓、iPhone 真机为准。
